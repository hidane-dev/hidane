hidane (火種, the seed of fire) — a Firestore emulator without Java.

A single Rust binary that replaces the official Cloud Firestore emulator. No JVM. Starts in milliseconds. Tested for parity against the official emulator.

$ curl -fsSL https://hidane.dev/install.sh | sh v0.4.0 · macOS · Linux

Installs the latest release in ~/.local/bin, checked against its SHA-256. Homebrew, npm (Windows too), cargo and Docker: Install.

Why hidane

21

Java 21 is now required

firebase-tools 15 dropped support for Java older than 21. Running a local database should not require a JDK.

Source: firebase-tools v15.0.0 release notes
0.74 s · 95 MiB

0.74 s to start, 95 MiB idle

The official emulator takes 0.74 s to open its port (2.5 s through the CLI) and sits at 95 MiB idle. hidane on main: 5.5 ms and 7.4 MiB.

Source: measurements and raw logs
11× slower

Writes slow down as data grows

With a listener attached, the official emulator's batch writes slow down in proportion to the number of documents: 11 times slower at 100k. hidane is designed so that a commit costs only what it changes: the same 100k documents take 4.9 s, flat per batch.

Source: measurements and raw logs

All figures are measurements, but not side by side: hidane's were taken later on a quieter machine, and a same-machine comparison is coming. Context: why hidane.

Parity

hidane treats the official emulator as the oracle: its answers are recorded, and the test suite replays every recording against hidane. No claim of compatibility without a test behind it.

So far: 20,224 answers of the official emulator in 41 recordings, each replayed against hidane in CI, and SDK transcripts from both emulators compared side by side (results). How they are counted: docs/parity.md.

Roadmap

  1. v0.1

    Server SDKs and native clients: firebase-admin, the Google Cloud libraries, iOS, Android and Flutter, running under firebase-tools.

    v0.1 milestone on GitHub
  2. v0.2

    Security Rules, evaluated once per request as the official emulator decides them: reads, writes, listeners and queries, measured against it case by case, with its compiler warnings, rule coverage reports and debug() output. Released in v0.2.0; v0.2.1 feeds the Emulator UI's request monitor, and @firebase/rules-unit-testing is verified end to end, in Node and in the browser.

    v0.2 milestone on GitHub
  3. v0.3

    Browser clients: firebase-js-sdk in the browser and Flutter Web. Released in v0.3.0: the SDK's own browser test suite passes on hidane as on the official emulator, 1,183 tests in Chromium, and Flutter Web is verified.

    v0.3 milestone on GitHub
  4. v0.4

    Functions triggers: Firestore events delivered to the Functions emulator, v1 and v2, under firebase emulators:start. Released in v0.4.0: the events are recorded from the official emulator and replayed, and functions receive the same data end to end.

    v0.4 milestone on GitHub
